# ADR-0003 — 全局单版本模型：切换先卸载再装

- **状态**：Accepted
- **日期**：2026-08-29
- **背景**：早期设计假设\"多版本并行、版本目录独立\"。用户明确裁定：**全局只有一个 dsh 版本**，启动器只是管理介质；切换版本 = 先卸载当前版本、再安装目标版本（Q14）。工具链（Node/Git/pnpm）同样**直接全局安装、单个版本**，不走用户级目录 + PATH 注入（Q16）。

## 决策

1. dsh 以**全局安装**（npm 全局 / 全局工具链）形式存在，同一时刻仅一个激活版本。
2. 版本切换 = 卸载旧 → 安装新。更新 = 覆盖升级到最新（npm 通道 `npm i -g @deepseek-ai/dsh@latest`；GitHub 通道重新 clone + 构建）。
3. 工具链全部走官方通道全局安装，**无用户级目录选项**。网络问题由**镜像源配置**解决（npm registry / GitHub 加速分开配置）。
4. 运行目录（workspace root）：**不配置**，以 dsh 官方行为为准——dsh 将启动时 CWD 作为默认 workspace 根目录，启动器不干预、不校验。

## 理由

- 用户明确\"全局单个版本避免所有问题\"：避免多版本 PATH 冲突、环境变量混乱、磁盘冗余。
- 工具链与 dsh 都全局化后，启动器职责收敛为：**检测、提示、一键安装、生命周期控制、日志**。
- 镜像源配置取代\"用户级目录\"作为网络问题的解决手段，更符合\"官方通道\"原则。

## 后果

- 卸载前必须**优雅停止 dsh**（SIGTERM，ADR-0002）。
- 卸载时提供**滑动开关**：可选是否保留 DSH_HOME（默认保留，不碰用户数据）。
- 升级/卸载前**默认不备份** DSH_HOME（代码升级不写用户数据）；提供手动"导出 DSH_HOME 备份"按钮。
- 全局安装需要**管理员权限**（Windows 下 npm 全局目录在 `%APPDATA%\npm` 通常免管理员，但 Git 安装需要；主进程不常驻管理员，提权步骤走 runas 子进程）。
- **离线包**：dsh 源码 tar.gz/zip（用户手动从 GitHub Release 下载），解压后本地构建（pnpm install + build），工具链仍需在线/镜像。
