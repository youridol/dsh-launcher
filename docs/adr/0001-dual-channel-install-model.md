# ADR-0001 — 双安装通道模型：GitHub 源码通道与 npm 通道

- **状态**：Accepted
- **日期**：2026-08-29（按工作区时钟）
- **背景**：需求要求"GitHub 官方在线安装通道 + npm 官方安装通道"，且"基于 v0.1.2-alpha.1 及更新版本"。事实核查发现：`v0.1.2-alpha.1` 是 GitHub 纯源码 tag，**npm registry 上不存在该版本**（npm 最新为 `0.1.1-rc.2`，10 个版本）。

## 决策

两个通道**互相独立**，各自维护各自的版本列表，版本号不强行统一：

1. **GitHub 源码通道**：从 GitHub Releases 拉取 `v0.1.2-alpha.1` **及更新版本**的源码 tag，clone 后执行 `pnpm install` + `pnpm run build` 从源码构建。适合想要最新/定制版的人。
2. **npm 通道**：读取 registry 现有版本（`@deepseek-ai/dsh`），当前实际可用到 `0.1.1-rc.2`。用 `npx @deepseek-ai/dsh` 或本地安装运行。

版本选择器 UI 显示**各自通道的真实可用版本**，不做跨通道版本对齐。

## 理由

- npm 上不存在 v0.1.2-alpha.1，强行"两个通道都只认 ≥ v0.1.2-alpha.1"会让 npm 通道无版本可装。
- 两个通道产物形态（预装包 vs 源码构建）与依赖（Node only vs Node+pnpm）天然不同，强对齐无意义。
- 用户明确："GitHub 只认 v0.1.2-alpha.1 及更新；npm 读取当前 npm 仓库现有版本，因为 v0.1.2-alpha.1 有大改、区别于旧版。"

## 后果（2026-08-29 修订：单版本全局模型）

- 版本管理数据模型为"通道 × 版本"二维结构，但**全局只激活一个版本**：切换版本 = 先卸载当前、再安装目标（见 ADR-0003）。
- 后续新增二进制发布（若官方开始出打包产物）可扩展为第三通道，不影响本决策。
