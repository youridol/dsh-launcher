# ADR-0004 — 启动器版本号策略：非标准十进一递进

- **状态**：Accepted
- **日期**：2026-08-29
- **背景**：AGENTS.md 要求发版判型（PATCH/MINOR/MAJOR）并同步三处版本号。用户明确版本策略为：**启动器版本独立于 dsh，从 0.1.0 起，0.0.1 递进，0.1.9→0.2.0 十进一递进**。这**不是语义化版本（SemVer）**——`0.1.9 → 0.2.0` 在 SemVer 中是 MINOR 递进（`0.x.y` 下 `x` 是 MINOR），用户的意思是纯十进制滚动。

## 决策

- 版本号 `X.Y.Z`，每次发版 `Z` +1（0.0.1 递进）；`Z` 到 9 后 `Y` +1、`Z` 归 0（0.1.9 → 0.2.0）；`Y` 到 9 后同理进 `X`。
- **放弃 AGENTS.md 的 PATCH/MINOR/MAJOR 判型语义**（该判型针对语义化版本；本项目采用十进一滚动，判型仅用于决定是否需要发版）。
- 三处同步仍遵循：`package.json` + `src-tauri/Cargo.toml` + `src-tauri/tauri.conf.json`。
- `CHANGELOG.md` 顶部插中文条目规则不变。

## 理由

- 用户明确指定，且十进一滚动在桌面工具类产品中常见（简单、无预发布复杂度）。
- 与 dsh 版本（0.1.2-alpha.1 等 alpha/rc）彻底解耦，避免混淆。

## 后果

- 语义化版本工具（如 `npm version`、cargo-release）的自动递增**不适用**，需手动维护或自定义脚本（十进一逻辑）。
- 发版时无需判断 PATCH/MINOR/MAJOR 归属，只需决定"本次是否发版"。
- 版本选择器（UI）中 dsh 版本与启动器版本分开展示。
